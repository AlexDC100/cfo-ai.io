### A2 — PADDING, AND A FLOOR WITH EIGHT UNITS OF HEADROOM

**The attack, two halves.**

(a) An EXPORTED component referenced from nowhere, holding four tags with
real provenance expressions, added to a file that is already imported.
Delete four REAL findings affordances, update the registry HONESTLY, and
the census prints `units=76`, findings `10`, PASS.

(b) `FLOOR_AFFORDANCES = 68` against a measured 76 meant **eight real
affordances could be deleted with honest registry updates** and the gate
stayed green.

**The close (R7 + R8).**

(a) Reachability, measured two ways and both PROVABLE from the tree — the
gate refuses only what it can prove inert:

* the FILE holding a bearing tag must be imported by something (static
  `from` or dynamic `import()`) or be an app entry;
* the COMPONENT enclosing the tag must be NAMED somewhere outside its own
  declaration — rendered, imported, re-exported, lazily loaded. The one
  exception is a file's DEFAULT export, which a router reaches through the
  file and never through the name.

(b) Floors became two checks, neither with headroom:

* the **DERIVED floor** — the registry's own `affordances` numbers, summed
  globally and per surface. Printed on the header line
  (`derived registry total 76`) and red when it disagrees with the tree at
  a level that names the surface.
* the **RATCHET** — `RATCHET_AFFORDANCES = 76` and a per-surface `ratchet`
  set to the measured count, EXACT. A deletion reds **even when the
  registry is updated honestly**, because the registry records what the
  tree says today and the ratchet records what the product HAD. Raising is
  free (the gate prints a NOTE); lowering is an edit that has to say which
  affordance was retired and why.

Discovery floors (files, sites, producers) keep their headroom on purpose:
sites move with ordinary refactors, and those floors catch a walk that
stopped walking, not a deletion.

### A4 — DISCOVERY MISSED WHOLE FILES, TWO WAYS

**The attack.** A new file painting 12 figures:

* six through an exported `spellRon()` / `spellPct()` — invisible, because
  the sweep only matched names beginning `fmt` or `format`;
* six through a local `money()` built on `Math.round` and a
  thousands-grouping regex — **not even counted as a producer**, because
  `FIGURE_SPELLING` listed native formatters and a roster of names, and a
  grouping regex is neither.

**The close (R6). Discovery is by BEHAVIOUR, not by name.**

* `FIGURE_SPELLING` now includes the **thousands-grouping regex**
  (`\\B(?=(\\d{3})+(?!\\d))` and its variants — the only reason anyone
  writes a lookahead over digit triples), alongside the natives.
* A name-agnostic sweep over every exported declaration under `frontend/`
  classifies each by what its body DOES:
  * a **FORMATTER** returns display text spelled from a number — its CALLS
    are figure render sites;
  * a **PRODUCER** spells figures inside and returns a STRUCTURE (a
    statement object, a workbook, an HTML document) — its own internal
    spellings are the sites, counted in its own file.
  Getting this backwards either way has a real cost, and both directions
  were measured: treating every producer as a formatter makes
  `buildBSStatement()` a "figure render site" (16 false positives);
  treating every formatter as a producer is how `CompareTray.tsx` rendered
  16 figures in no roster at all.
* The 17 formatters behaviour finds today are counted whether or not
  anyone rosters them (`--dump-formatters` prints each with the return
  expression that classified it). All 17 happen to be rostered already,
  so the roster is currently honest — and it can no longer be the thing
  that decides what counts.

**Two scanner bugs found by building the plant, both under-counts** — the
one direction a census must never drift:

* `function NAME(` local helpers had their body read from just after the

### A5 — THE SOURCE LINT: THREE OF THE SEVEN EVASIONS, CLOSED

**The attack.** Seven ways to spell the same absent-to-zero substitution.
The lint caught three (`Number(x) || 0`, a bag-lookup chain, a
`JSON.parse` chain) and walked past these three, which are not exotic —
they are the three most ordinary spellings there are:

| | evasion |
|---|---|
| (a) | a helper that hides it — `const or0 = (x) => x ?? 0`, then `or0(row.opening)` |
| (b) | a destructuring default — `const { opening = 0 } = row` |
| (c) | a null-test ternary — `x == null ? 0 : x` |

**The close (R11).** All three matched on their SHAPE:

* (a) any local one-liner that turns its own parameter into 0 — by `??`,
  by `||`, by a null-test ternary, or by `Number.isFinite(x) ? x : 0` — is
  a zero-substituting helper **whatever it is called**, and its calls are
  substitutions. Name-agnostic, because a roster of names is the thing
  this gate keeps being broken by.
* (b) a destructured numeric default off any identifier or member chain.
  A builder's parameters are payloads by construction, so the source is
  not required to be a member chain; the existing figure/non-figure field
  tests still keep an options bag's `{ timeout = 0 }` out.
* (c) `X == null ? 0 :` and `Number.isFinite(X) ? X : 0` — the `??`
  written long-hand, and the same thing wearing a guard that looks like
  diligence.

**PLANT A5** — all three appended to `buildBsStatement.ts` (in scope: it
feeds a card-bearing surface):

```
const or0 = (x: number | null | undefined) => x ?? 0;
export function __a5Plant(row: {…}) {
  const openingCents = or0(row.opening);                    // (a)
  const { closing = 0 } = row;                              // (b)
  const amountCents = row.amount == null ? 0 : row.amount;   // (c)
  …
}
```

```

    substitution(s), measured 19. A new absent-to-zero needs a verdict
    before it ships; a removed one is progress and re-states the entry.
```

**16 → 19: all three.** `--dump-leaf` names them:

```

   :1276  closing = row.closing = (destructuring default) 0
   :1277  amount = row.amount == null ? 0
```

REVERTED → PASS, and the lint finds **no new hits on the real tree** (134,

**STATED PLAINLY, because the critic asked for it:** the source lint is

same substitution are reachable — a zero coming back from an imported

## R5 — THE AXIS THE GATE DID NOT HAVE: IS THE FIGURE REAL?

Everything above is a census of CALL SITES. It asks whether a site RECORDS
a verdict; it cannot ask whether the number arriving there is one the
engine served. The critic put it exactly: **every fabrication happens in a
BUILDER, upstream, so the value reaches the affordance as a finite number
and all five of its guards correctly wave it through. The guard is
downstream of the lie.**

The gate now has the axis, in two places.

### (a) A SOURCE LINT over the builder layer — `GATE-WORK provenance-absent-leaf`

**SCOPE is derived, not hand-listed:** the modules a card-bearing
component imports directly, resolved from the import graph. A builder that
starts feeding a provenance-bearing surface enters scope on its next run
with no edit to the gate. Measured: **79 modules feeding 27 card-bearing
components**, floored at 70 so a broken walk cannot make the lint pass by
examining nothing.

**THE SHAPE IS NARROW ON PURPOSE.** A blanket ban on `?? 0` over the whole
reachable set is 434 hits, most of them accumulator seeds and index
guards, and a 434-entry allowlist is a rubber stamp rather than a gate.
What is banned is the shape that actually fabricates: an absent PAYLOAD
LEAF — a member chain, a call on one, or a local holding one — substituted
by `0`, by a DIFFERENT field, or by an arithmetic expression over other
terms. Names are normalised camelCase → snake_case and tested both ways, so
`accountCode ?? split?.code` (a code) and `basePath ?? location.pathname`
(a route) are not figures and do not red. **`?? NaN` / `?? null` never
reds** — that is the CORRECT refusal, the one `isAbsentFigure` catches.

**Proven against all three live fabrications.** The source lane landed F1
and F3 while this was being built, so each was re-planted to prove the lint
sees it:

```

      :313  differenceCents = servedDifference ?? assets - el
F2  publicCompanyAdapters.ts (22) + financialReport.ts (3, incl. safeDiv)

REVERTED (F1 + F3 plants)   159 substitutions, both lines gone
```

F3's exact shape needed two widenings the first draft did not have: the
substitute may be an ARITHMETIC EXPRESSION (`?? assets - el` invents a
perfect balance out of the terms still present), and the left operand may
be a LOCAL that holds a payload leaf (`servedDifference`) rather than a
member chain — a "must contain a dot" test walks straight past the
fabrication it was written to catch.

**THREE buckets, and the third is the honest one.**

| Bucket | Meaning | Count |
|---|---|---|
| `FILED_ZERO` | checked against a real envelope; the zero is filed, or no figure is painted from the field | 4 |
| `OPEN_DEFECT` | PROVEN to fabricate against a real fixture; carries an `owner`; `CEILING_OPEN_DEFECT` only falls | 25 |

than about the payload, which would be invented. Both ceilings are
ratchets: a new fabrication does not get to hide behind an existing one's
allowance, and each file is re-bucketed as it is run against
