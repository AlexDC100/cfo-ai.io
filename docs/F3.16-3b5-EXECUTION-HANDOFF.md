## Step 1 — Run the schema migration (Supabase Studio)

Open Supabase Studio → SQL editor → paste the body of
`supabase/schema_phase_3b5_pre_backfill_snapshot.sql` (everything
above the ROLLBACK BLOCK section). Click Run.

Verify with a quick column check (also in Studio):

```sql
SELECT column_name, data_type
  FROM information_schema.columns
 WHERE table_name = 'financial_periods'
   AND column_name = 'pre_backfill_snapshot';
```

Expected: one row, `pre_backfill_snapshot | jsonb`.

If the row is absent, the migration didn't run; do NOT proceed.

## Step 3 — Phase 1a: single-period diff (the safety net)

```bash
ssh root@<VPS> 'docker exec cfo-ai-backend python3 /app/scripts/run_3b5_backfill.py --mode single' | tee /tmp/3b5-single.txt
```

This re-extracts the smallest period (EEI PDF, 61 line_items) and
diffs the new envelope against the snapshot.

**Pass criteria:**
- `Δ total_assets` within ±0.5%
- `Δ current_year_pnl` within ±5%
- `round_trip_check.passed = True`
- Envelope present

**On HALT:** the script prints the affected `period_id`. Run
`--mode rollback`, paste the SQL into Supabase Studio with the
period_id substituted, and stop. The Carniprod ADR prediction is
the priority signal — if the orchestrator HALTed but the period_id
is NOT Carniprod (Carniprod isn't in the backfill set anyway), the
re-extract mechanism itself is broken on this fixture; do not
batch.

If everything is clean, immediately re-run F-A3.1 + F-A3.2 to
confirm calibrated fixtures haven't moved:

```bash
ssh root@<VPS> 'docker exec cfo-ai-backend python3 /app/scripts/measure_bs_drift.py'
ssh root@<VPS> 'docker exec cfo-ai-backend python3 /app/scripts/measure_cross_path.py'
```

Must remain 8/8 GREEN. **Carniprod = 7.3939%** (canary).

## Step 7 — Browser-equivalent spot-check (per ADR Lock #6)

Pick two random period IDs from the backfilled set. Curl the period
detail endpoint for each and verify response shape matches the
pre-backfill view (the F3.15 fallback was producing the same
user-visible numbers; the change is the underlying envelope source,
not the displayed values).

```bash
# Replace <pid> with two of the backfilled period IDs.
curl -s "https://cfo-ai.io/api/period/<pid>" -H "Authorization: Bearer <jwt>" | jq '.balance_sheet.total_assets, .pnl.current_year_pnl, .assembled_canonical_v1.schema_version, .assembled_canonical_v1.round_trip_check.passed'
```

Expected:
- Numbers within tolerance of pre-backfill (operator may want to
  pull pre-snapshot numbers via Supabase Studio for direct compare;
  the orchestrator's own diff is the binding gate, this is the
  extra eyes pass).
- `schema_version = "canonical_v1.0.0"`
- `round_trip_check.passed = true`

## Rollback decision tree

| Trigger | Action |
|---|---|
| Single-period HALT | `--mode rollback` for that period_id, do NOT batch. Diagnose. |
| Batch HALT (any reason inside a batch) | `--mode rollback` for affected period_id(s), STOP. F-A3.1 must be re-confirmed before retrying. |
| F-A3.1 RED post-batch | Rollback the batch's period_ids. Carniprod is the canary. |
| F-A3.2 RED post-batch | Same — cross-path divergence shouldn't surface from a backfill. |
| F-A3.3 RED post-batch-2 | Coverage gap. Rollback the offending period_ids. F3.15 fallback stays alive until F-A3.3 is GREEN. |
| User-visible field shifts unexpectedly on spot-check | Rollback that period. Either re-investigate the source doc or accept and proceed (operator judgment). |

## What happens AFTER 3b.5 succeeds

3b.5 phase 3 — **F3.15 fallback deletion** — ships in its own PR,
a separate day, with the operator confirming F-A3.3 is GREEN and
stable for 24-48h before the deletion ships. Deletion is
irreversible (the fallback gets replaced with a hard error). Do
NOT bundle deletion into the same session as the backfill.

3b.6 — **F4.2 hardening + consumer cutover** — ships next.
Design plan: `docs/F3.16-3b6-f42-hardening-plan.md` (delivered
this session in parallel).

After 3b.5 (backfill + deletion) and 3b.6 (F4.2 hardening +
cutover) ship, the F3.16 sprint closes. RO-pack architectural
debt is paid down at that point.
