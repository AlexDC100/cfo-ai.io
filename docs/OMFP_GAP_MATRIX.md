# OMFP 1802 Classification — Gap Matrix

The RO classification subsystem has three stacked layers: (1) a locked prefix→bucket table `_RULES` in chart_of_accounts.py:76-496 resolved longest-prefix-first by `bucket_for()` (chart_of_accounts.py:499-506), with a Romanian-keyword name fallback `bucket_for_name()` (chart_of_accounts.py:637-650); (2) a deterministic parser layer (trial_balance_parser.py) that converts TB rows to signed amounts using bucket membership sets (CREDIT_POS_BS/DEBIT_POS_BS etc., trial_balance_parser.py:721-739) plus an 8-prefix side-flip list for bifunctional class-4 accounts (trial_balance_parser.py:753-762); and (3) a post-hoc canonical adapter (canonical_adapter.py:60-302) that re-routes the already-assembled line_items into canonical_v1 buckets — meaning any account the legacy table drops never reaches the canonical layer, and the two layers disagree in several places (151, 166, 4426, 59x). Signs work by combining a side-aware amount computation in the parser with rule.sign multiplication in assemble_statements (chart_of_accounts.py:1138), then a bucket-LEVEL abs() flip on liability/equity fields (chart_of_accounts.py:1204-1211). Contra-asset families (28x/29x/39x/49x/59x) correctly subtract from assets, and 129/117/121 equity mechanics are solid including the class-6/7 reconstruction vs 121-anchor cross-check (silent 5% override, chart_of_accounts.py:1375-1378). The big systematic hole is bifunctional accounts: only 8 prefixes flip sides; 4111-credit, 401-debit, 462-debit, 473-credit, 4424/4426/4428 wrong-side, and 5121-credit all land as NEGATIVE lines inside the natural-side bucket instead of being reclassified — understating both sides of the BS simultaneously, which is exactly the residual class that feeds the Assets≠E+L drift the audit is mapping. Unmapped accounts behave differently per path (silent drop with zero telemetry on the deterministic path; surfaced+name-fallback on the Claude path), class 8 is excluded only by fall-through on the XLSX path, and the rules table itself carries no mapping_version — persisted periods cannot be tied to the rule vintage that produced them.

## Risks per gap
- **(a) Contra 28x/29x subtract from assets** [EXISTS]: Edge defect: for sign=-1 accounts the parser takes `sf_d if sf_d != 0 else sf_c` (trial_balance_parser.py:863) — a contra account carrying BOTH sides nonzero picks the debit side and the contra is lost. Also no bare "28" catchall: a novel 28x subcode drops silently (deterministic path) or can name-fallback to P&L "depreciation" via the "amortizare" keyword (chart_of_accounts.py:615-617) on the Claude path.
- **(a) Contra 39x subtracts from inventory** [EXISTS]: Minimal; a hypothetical bare "39"/"390" code would fall to the "3" catchall sign=+1 (chart_of_accounts.py:199) and ADD to inventory.
- **(a) Contra 49x subtracts from AR** [PARTIAL]: Unmapped 49x provision accounts are silently dropped on the deterministic path (trial_balance_parser.py:779-780) → AR overstated by the missing allowance; asset side inflates relative to E+L.
- **(a) Contra 59x subtracts from treasury** [EXISTS]: Legacy/canonical disagree on which asset line 59x reduces (cash vs AR); totals unaffected, line-level views diverge.
- **(b) 129 contra-equity** [EXISTS]: None material.
- **(c) 169 / 269 netting** [MISSING]: Companies with bond financing or 166-family affiliated loans get those balances silently dropped → liabilities understated → direct Assets>E+L drift; 169 debit balances that should net against debt are also dropped.
- **(d) Bifunctional accounts by final-balance side** [PARTIAL]: Every unflipped wrong-side balance nets a negative line into the natural-side bucket, understating BOTH assets and liabilities by the same amount — invisible to a naive drift metric yet structurally wrong, and the residual class behind the reported BS-tab asymmetry. Worse, the bucket-level abs() flip (chart_of_accounts.py:1204-1211) inverts a legitimately net-negative liability bucket wholesale, fabricating positive liabilities from what is economically an asset.
- **(d) 5121 credit balance → ST bank debt, not negative cash** [MISSING]: An overdrawn account shows as negative cash instead of short-term bank debt: cash, total_debt, current ratio, and net-debt/EBITDA are all mis-stated; assets and liabilities simultaneously understated.
- **(e) 121 credit=profit/debit=loss in equity + class7−class6 cross-check** [PARTIAL]: The cross-check is a silent substitution — no flag/field records that the override fired or by how much (grep: no anchor_applied/divergence emission). A >5% class6/7-vs-121 gap (missing accounts, broken extraction) is masked instead of surfaced, weakening the audit trail for exactly the reconciliation the methodology (Gate 1) requires.
- **(f) 117 either side in equity** [EXISTS]: None material.
- **(g) TVA routing 4423/4427 liability, 4424/4426 asset, 4428 by side** [PARTIAL]: Any pre-settlement monthly TB (4426/4428 carrying balances) mis-sides VAT: current assets understated, current liabilities understated by the same negative amount; the legacy and canonical layers also disagree on 4426, so the two envelopes diverge on the same period.
- **(h) 471/472/475/478 deferred items** [EXISTS]: None material.
- **(i) Class 6/7 balances → result into equity, never 6xx as assets** [EXISTS]: Adjacent defect: for 711/712 the parser takes the side with LARGER absolute value, not the D/C net (trial_balance_parser.py:871) — on SAGA-format files where 711 debits and credits accumulate independently this overstates inventoryVariationMemo, contaminating ebitda_statutory_with_711 and total_operating_revenue_statutory (chart_of_accounts.py:1403-1407).
- **(j) Class 8 and 891/892 excluded** [PARTIAL]: On the Claude/direct assemble path, unmapped 8xx accounts hit the semantic NAME fallback (chart_of_accounts.py:1068-1084): e.g. 8034 "Debitori scoși din activ" contains "debitori" → routed to "ar" (chart_of_accounts.py:608), leaking off-balance memo amounts into assets. Exclusion-by-fallthrough is one keyword match away from failure.
- **(k) Current/non-current split (161-167 LT, current portions, 519 ST, 151)** [PARTIAL]: Bond/affiliate LT funding vanishes from liabilities entirely (drift toward Assets>E+L); the 151 disagreement shifts current-liability totals between the legacy envelope the FE renders and the canonical envelope used for methodology formulas — same period, two different current-ratio denominators.
- **(l) Sign normalization mechanism + where a credit-balance asset ends up** [DEFECT]: Two Assets=E+L hazards: (1) wrong-side balances net invisibly inside buckets rather than being reclassified — per-account misstatement with zero drift signal; (2) the bucket-level flip is per-TOTAL, not per-account, so one large debit-side 442/473/461 balance can drag a whole liability bucket negative and get abs()-flipped, ADDING a fabricated liability equal to twice the residual.
- **Unmapped-account handling (path-divergent)** [DEFECT]: The production fast path (deterministic parser) is the one with ZERO unmapped telemetry — precisely where novel accounts (169, 166, 493-498, class 8) drop. Missing balances are invisible to both the FE transparency block and the drift gates; a one-sided drop directly produces Assets≠E+L.
- **bucket_for() fallback behavior** [EXISTS]: Fallback asymmetry: the same account in the same file classifies differently depending on ingestion path (deterministic drop vs name-keyword routing).
- **Rule versioning / mapping_version** [MISSING]: A period analyzed before a rule change (e.g. 168 moving from interestExpense to ltDebt, chart_of_accounts.py:122-139) is indistinguishable in the DB from one analyzed after; cross-period comparisons and cached snapshots silently mix classification regimes, and regressions like the F1.f/F1.j container-drift incident cannot be attributed to a rules version.
