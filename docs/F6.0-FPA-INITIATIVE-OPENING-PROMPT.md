## Why this initiative exists
Competitive audit (June 2026) revealed CFO AI is positioned as "benchmarking with light FP&A." Direct competitors in the SMB FP&A category (Mosaic, Causal, Jirav, Cube, Pry) all ship six features CFO AI lacks. Closing this gap is required to position CFO AI as "FP&A platform with benchmarking as differentiator" — the strategic positioning the audit identified as defensible.

## What ships in this initiative

Six features in DEPENDENCY ORDER (not the audit's listing order — the audit listed by user-visible impact, not engineering dependencies):

| Phase | Feature | Why this order | Estimated sessions |
|-------|---------|----------------|---------------------|
| F6.0.1 | Period Comparison Everywhere | Foundation. Required infrastructure for #2 and #5. | 1-2 |
| F6.0.2 | Excel + PDF Export | Independent. Quick win. Ships in parallel with anything. | 1 |
| F6.0.3 | Variance Analysis (Actual vs Budget vs Prior Year) | Depends on F6.0.1 (multi-period infrastructure) and dataset tagging | 1-2 |
| F6.0.4 | Configurable Dashboard | Independent. Closes loop on F5.0 learning system. | 1-2 |
| F6.0.5 | Scenario Planning / What-If Modeling | Depends on F6.0.3 (variance baseline math). | 2-3 |
| F6.0.6 | Three-Statement Modeling (linked P&L + BS + CF) | Depends on F6.0.5. Heaviest. Database schema changes. | 3-4 |

Total estimated effort: 9-14 sessions over 6-10 weeks.

## Sequencing locks

- F5.0 Phases 2-5 MUST close before F6.0 launches. Learning system is the competitive wedge; do not abandon mid-build.
- F3.16 Bug #4 holding pattern continues throughout. Bug #4 re-probe takes priority over F6.0 work if Supabase ticket clears.
- Each F6.0.x phase MUST close (verification gates passing, no open regressions, audit-trail documented) before F6.0.(x+1) launches.
- DEPENDENCY ORDER is non-negotiable. Building variance analysis before period comparison is half-broken work that produces incorrect math. Building scenarios before variance gives users no baseline to vary against.

## Verification discipline

Browser-only audit is INSUFFICIENT for features that touch financial math. Per Lock #15 (audit-trail), each phase requires:

1. Automated test suite for the new computation paths (multi-period reconciliation, variance math, three-statement linking)
2. Wrong-on-purpose test (Lock #12) — deliberately break a known case, confirm test catches it
3. Visual verification in browser on desktop AND mobile (real device, not DevTools)
4. Pre-activation review checklist signed by operator before any production deploy
5. Diff summary listing every file touched with one-line rationale
6. Resume paragraph for the NEXT phase's launch session

If verification gates can't be met in one session, the phase is split into two sessions. Never compromise gates for speed.

## What this initiative is NOT

- NOT a feature checklist to copy from Mosaic/Causal. Each feature ships in a way that fits CFO AI's audience (Romanian SMB CFOs, finance directors) and integrates with the F5.0 learning system.
- NOT a pause-everything-for-FP&A sprint. F3.16 Bug #4 and F5.0 closure take priority.
- NOT a justification for bypassing pre-activation review on financial-math features.
- NOT a multi-session megaprompt. Each phase is its own session with its own opening prompt, its own verification gates, its own SAGA entry.
