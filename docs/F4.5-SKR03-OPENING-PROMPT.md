## 1. Scope

F4.5 ships the **German SKR03 country pack** — the second country pack on the
canonical chart schema (F4.0). The deeper purpose is a stress test of F4.0
itself: the canonical schema was designed against Romanian RAS, calibrated on
8 Romanian fixtures (EEI, Scandia, Sibiu, Frozen, RealEstate, Agras, Carniprod,
Retail), and locked at <0.5% drift across all of them. F4.5 answers whether
that schema is **actually country-agnostic** or whether the abstractions baked
in are RAS-shaped artifacts we didn't notice.

The deliverable: SKR03 trial balances → `assembled_canonical_v1` rows with
drift ≤ each fixture's F-A3.1 threshold (same gate discipline as F3.7c-f).

**Pacing.** ~6-10 sessions per the closure-ADR ledger reference for new
country packs. Engineering closure ≠ calendar closure — see Lock #14 / the
"Engineering vs calendar closure" entry in the F3.16 closure ADR. Do not
calendar-lock before invariants are verified empirically.

**Out of scope** — see §7.

## 3. SKR03 Sub-Questions That Will Stress-Test the Schema

These are the dimensions where SKR03 differs from RAS in ways that may
break F4.0's country-agnosticism. Session 1 must enumerate ALL of these
against an SKR03 spec doc (operator provides a sample chart) before
touching code. Each "✗" below is a hypothesis to verify in Session 1's
mapping spec, **not** a confirmed gap:

| Dimension | RAS (today) | SKR03 (hypothesis) | Schema risk |
|---|---|---|---|
| Account code length | 3-7 digits (`121`, `4111`, `5121`) | 4-digit standard (`0000`-`9999`) | Adapter's prefix-matching logic may assume RAS variability |
| Sign conventions | Debit/credit per RAS, contra-asset class 28x/49x reduce gross to net | Different German contra accounts (`Gegenkonten`); sign rules for 8000s/9000s revenue may invert | Net-vs-gross logic in canonical mapping may double-flip |
| Sub-totaling conventions | RAS computes via account-class roll-ups (1→equity, 6→exp, 7→rev) | SKR03 uses operating result (`Betriebsergebnis`) vs financial result (`Finanzergebnis`) explicit split | F4.0's `core_ebitda` vs `pnl_financial_result` split may misbucket |
| Fiscal-year-end norm | Dec 31 dominant in RAS | Dec 31 standard but ±3-month variants (Apr, Jun, Sep) common | Period-detection logic if it ever assumes calendar-year boundaries |
| VAT / tax handling | Class 44 mixed, 442x debit recoverable, 441 credit payable | SKR03 uses 1576/1776 (Vorsteuer / Umsatzsteuer) with explicit period accounts | Mixed-class netting logic may not generalize |
| P&L structure | Single op-vs-fin-vs-tax cascade | Operating result / financial result separation more explicit; potentially with material/personnel/D&A breakouts as first-class sub-totals | The "EBITDA reported vs adjusted" surface decision may not have a 1:1 mapping |

This list is the **starting set** for Session 1's spec doc. Add to it as
the SKR03 sample reveals more.

## 6. Pre-Locked Predictions (Lock #8 placeholder)

Session 1's mapping spec must end with an explicit **Pre-Ship Predictions**
block, structured per Lock #8:

```
For each fixture in {SKR03-fixture-1, SKR03-fixture-2, ...}, I predict:
  - Total assets reconciliation drift: < X%
  - Total equity reconciliation drift: < Y%
  - EBITDA (reported) within ±Z RON-equivalent of expected
  - <other invariants>

Empirical backing for each prediction:
  - <fixture row evidence>
  - <prefix coverage % from methodology vs adapter>
  - <wrong-on-purpose harness result>
```

**No framework-consistency reasoning.** A prediction of the form "the
canonical schema is country-agnostic, therefore SKR03 will round-trip at
<0.5%" is exactly what Lock #8 forbids. The empirical backing must come
from running the adapter against actual SKR03 fixture data and observing
the result, even if that means Session 1 produces only ONE prediction
(against a single sample fixture) instead of a full set.

## 7. What's NOT in Scope

F4.5 is **trial-balance ingestion + canonical mapping only**. Explicitly
out of scope, file as separate sprints if needed:

- German tax filing automation (`Elster`, `USt-Voranmeldung`, etc.)
- SOX or German equivalent (`Compliance-Berichterstattung`) compliance reporting
- IFRS / German-HGB / US-GAAP cross-walk beyond the existing canonical schema's coverage
- Multi-entity consolidation (`Konzernabschluss`)
- Any non-trial-balance source — invoices, GL details, AR/AP aging, fixed-asset registers all separate
- FE surface changes beyond what's required to render `assembled_canonical_v1` rows from a German fixture (existing FE should "just work" via canonical contract)
- Live macro signal feeds for German news / GDELT German-language queries — separate sprint, not bundled

**If the operator asks for any of the above during F4.5, file it as a new
sprint in SAGA §9 and continue with the trial-balance scope only.**
