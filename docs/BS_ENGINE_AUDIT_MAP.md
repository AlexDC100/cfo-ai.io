## Ingestion: upload → parse → extraction → normalization

Trial-balance ingestion is a dispatch tree in stage_extract (src/engine/api/pipeline.py:583-1086): upload bytes are fetched from Supabase storage, classified by mime/extension (_classify_file, pipeline.py:431-447), then routed through up to four branches before a Claude Opus fallback. PDFs try a public-records short-circuit, then a deterministic PyMuPDF position-based TB parser (country_packs/ro_romania/pdf_ingester.py); XLSX/XLS tries a statutory F30/F10 detector+parser (_document_type_detector.py, _statutory_parser.py), then the deterministic XLSX TB parser (country_packs/ro_romania/trial_balance_parser.py) via RomaniaPack.parse_trial_balance (pack.py:379-403); anything that fails these — and ALL CSVs — is rendered to text and sent to claude-opus-4-7 with a broad JSON-schema prompt (pipeline.py:321-428, 988-1086). The deterministic paths keep the full 10-column row (si/r/st/sf D+C) internally but collapse it to {code, name, amount[, bucket_override]} in accounts_to_assemble_shape (trial_balance_parser.py:700-916) before stage_map hands it to the pack's assemble_statements (pipeline.py:1089-1120) — the lossy round-trip the audit context describes starts here, at ingestion's exit. Template recognition is header-regex + positional Debit/Credit pairing (Layout A 8-col Crystal Reports/Scandia, Layout B 6-col SAGA with synthesized closing balances, F3.9c abbreviated SI/RL/RC/SF dialects); WinMentor/SAGA/Ciel vendor fingerprinting exists only for PDFs, and XLSX fingerprinting is an explicit TODO (pack.py:374-376). Number parsing is per-cell heuristic with no per-document locale detection: the XLSX helper _to_number disambiguates by separator position (trial_balance_parser.py:487-539), the PDF path is hardcoded Romanian-only (pdf_ingester.py:59-111), and the statutory parser has its own smarter comma-guard variant (_statutory_parser.py:500-535) — three independent implementations that can disagree. The only source balance check that reaches production telemetry is compute_source_imbalance on the CLOSING pair only (Σsf_d vs Σsf_c, warn>2%, trial_balance_parser.py:620-666); it never halts the pipeline, is not computed at all on Claude/CSV/statutory paths, and no check anywhere validates the solduri-initiale, rulaje, or sume-totale pairs on the XLSX path. Nothing in ingestion stops a materially imbalanced source file — it flows through assembly, persistence, and the FE with at most a banner.

### [PARTIAL] 2. Source-format / template recognition — what actually exists
XLSX: no template registry — recognition is COLUMN_PATTERNS header regexes (trial_balance_parser.py:113-157) + positional pairing of bare Debit/Credit columns into SI→RL→ST→SF order (:205-259) + explicit-label pass 3 (:261-278). Layout A (8-col, 4 pairs, Crystal Reports/Scandia) and Layout B (6-col SAGA, 3 pairs, no final block — closing synthesized from si+r identity at :399-468) are the two supported shapes; F3.9c added abbreviated BLN_CONT / 'SI DEBIT' dialects (:114-126, 213-236). SAGA-compact/WinMentor XLSX are handled only insofar as they match these patterns — vendor fingerprinting exists solely for PDFs (ro_pdf_winmentor/saga/ciel/generic, pack.py:352-376) and the XLSX fingerprint slot is an explicit TODO ('Future F3.9 fingerprinting lands here; for now leave None', pack.py:374-376). A generic 4-column TB (cont, name, one D/C pair) is REJECTED by the deterministic parser — the lone pair maps to 'initial' and validation demands a cumulative OR final pair (:302-313) — so it lands on the Claude path. Separately, _document_type_detector.py:44-90 routes statutory F30/F10 vs TB via anchor regexes, defaulting to trial_balance on ambiguity.
**Risk:** Recognition failures are silent downgrades, not errors: every ParseError in the fast-path is swallowed and rerouted to Claude (pipeline.py:937-941, 551-555), so a mis-detected template changes the entire fidelity class of the period without any user-visible signal at upload time.

### [DEFECT] 3. Number parsing — Romanian vs anglo, per-document detection, mixing
Three independent implementations, none doing per-document format detection: (a) XLSX _to_number (trial_balance_parser.py:487-539) — per-CELL heuristic: both separators → rightmost wins; comma-only → ALWAYS Romanian decimal; dot-only → float() verbatim. (b) PDF _parse_ro_number (pdf_ingester.py:105-111) — hardcoded Romanian (strip dots, comma→dot), with _NUM_PATTERN ^-?[\d.]+,\d{2}$ (:59) rejecting anglo and integer-formatted tokens outright. (c) Statutory _to_float (_statutory_parser.py:500-535) — same dual-separator rule but with a comma-guard: comma-only is decimal ONLY if 1-2 trailing digits, else thousands.
**Risk:** Formats can mix freely within one XLSX because the decision is per cell. Concrete 1000× failure modes in _to_number: anglo '1,234' (=1234) → parsed 1.234; Romanian text cell '1.234' (=1234) → parsed 1.234. The statutory parser's guard proves the team knows the fix; the TB parser lacks it. Mitigated for true numeric Excel cells (pandas dtype=str yields dot-decimal repr) but live for text-formatted cells. On PDFs, an anglo- or integer-formatted export doesn't misparse — every row silently fails the 10-number requirement and the file dies as 'no account rows' (pdf_ingester.py:391-402), or worse, partially parses.

### [PARTIAL] 4. Source balance check (sum D = sum C per column pair)

Read-time: reconciliation Check 1 'Debits = Credits' (severity critical) in confidence/reconciliation_checks.py:76-89 runs only inside the /api/period confidence report (pipeline.py:5754) and silently skips when source_data_quality is absent.
**Risk:** No check exists for the solduri-initiale or rulaje pairs anywhere; sume-totale is checked only on PDFs and only as a log line. NOTHING gates or halts: a 5%-imbalanced source proceeds through assembly → persistence → FE with a banner at most, and on the Claude/CSV/statutory paths there is no source balance check at all (source_data_quality is never set — pipeline.py:1099 confirms 'Claude-extracted fallback, statutory F30/F10' default to None). The CLAUDE.md Appendix-B 'stop and ask' validate_trial_balance gate exists only in the standalone toolkit — grep confirms no engine counterpart. This means the known Assets≠E+L class of defect can be seeded at ingestion (dropped PDF rows, misparsed cells, Claude omissions) with drift telemetry blind to three of the four column pairs.

### [EXISTS] 5. Exact shape of 'parsed'/'accounts' handed to assembly
stage_map passes parsed['accounts'] to pack.assemble_statements (pipeline.py:1112-1120). One account row is {"code": str, "name": str, "amount": float(round 2)} with optional "bucket_override": "otherCurrentLiab" for credit-side class-4 side-flip prefixes (trial_balance_parser.py:798-803, 911-915; Claude path builds the same 3-key shape at pipeline.py:1048-1052; statutory path at _statutory_parser.py:799-806). Amount semantics are bucket-dependent and pre-signed: BS accounts carry sign-aware closing balance (sf_c−sf_d or sf_d−sf_c per rule.sign, trial_balance_parser.py:819-863), P&L accounts carry the larger-side YTD sume-totale movement with SAGA sign-flip fallback (:864-880), and 121 carries its signed closing balance as the statutory anchor under bucket ignore_control (:881-905). The parsed wrapper also carries company_name, period_label/period_end (filename-derived via _detect_period_end_from_filename + _sane_period_end clamps, pipeline.py:176-192, 1147-1184), currency, confidence, detected_type, statutory_net_profit_anchor, source_data_quality.
**Risk:** The 10-column source truth (si/r/st/sf, both sides) exists ONLY transiently inside stage_extract; assembly, persistence and the FE reassembly all operate on the collapsed single-amount rows, so any downstream reconciliation (including the Fix-A1 envelope overrides) can never re-derive per-pair balance from what was persisted — the lossy round-trip is locked in at this interface.

### [PARTIAL] 6. Failure behavior today (what stops vs what degrades)
Hard stops that mark documents.status=failed: public-records detected-but-unparseable (PublicRecordsUnparseableError, pipeline.py:710-721), Claude invalid JSON / overload after retries (pipeline.py:1005-1029), file >25MB (pipeline.py:810-811). Silent downgrades (log + fall through to Claude): every deterministic-parser ParseError/PdfIngestError (pipeline.py:551-555, 771-776, 886-892, 937-941). Silent continues: source imbalance of any magnitude (warn flag only), PDF row loss within tolerance, statutory-detection empty-rows fallback (pipeline.py:840-849).
**Risk:** The failure taxonomy inverts severity: format-shape problems (recoverable) can hard-fail, while numeric-integrity problems (the ones that corrupt Assets=E+L) never fail — they degrade or pass silently, which is exactly the propagation channel for the audited 39.19M vs 45.81M class of defect.

## RO classification rules (OMFP 1802) — gap audit

The RO classification subsystem has three stacked layers: (1) a locked prefix→bucket table `_RULES` in chart_of_accounts.py:76-496 resolved longest-prefix-first by `bucket_for()` (chart_of_accounts.py:499-506), with a Romanian-keyword name fallback `bucket_for_name()` (chart_of_accounts.py:637-650); (2) a deterministic parser layer (trial_balance_parser.py) that converts TB rows to signed amounts using bucket membership sets (CREDIT_POS_BS/DEBIT_POS_BS etc., trial_balance_parser.py:721-739) plus an 8-prefix side-flip list for bifunctional class-4 accounts (trial_balance_parser.py:753-762); and (3) a post-hoc canonical adapter (canonical_adapter.py:60-302) that re-routes the already-assembled line_items into canonical_v1 buckets — meaning any account the legacy table drops never reaches the canonical layer, and the two layers disagree in several places (151, 166, 4426, 59x). Signs work by combining a side-aware amount computation in the parser with rule.sign multiplication in assemble_statements (chart_of_accounts.py:1138), then a bucket-LEVEL abs() flip on liability/equity fields (chart_of_accounts.py:1204-1211). Contra-asset families (28x/29x/39x/49x/59x) correctly subtract from assets, and 129/117/121 equity mechanics are solid including the class-6/7 reconstruction vs 121-anchor cross-check (silent 5% override, chart_of_accounts.py:1375-1378). The big systematic hole is bifunctional accounts: only 8 prefixes flip sides; 4111-credit, 401-debit, 462-debit, 473-credit, 4424/4426/4428 wrong-side, and 5121-credit all land as NEGATIVE lines inside the natural-side bucket instead of being reclassified — understating both sides of the BS simultaneously, which is exactly the residual class that feeds the Assets≠E+L drift the audit is mapping. Unmapped accounts behave differently per path (silent drop with zero telemetry on the deterministic path; surfaced+name-fallback on the Claude path), class 8 is excluded only by fall-through on the XLSX path, and the rules table itself carries no mapping_version — persisted periods cannot be tied to the rule vintage that produced them.
